## 2. 架构与依赖关系

```
[调度 agent] --委派(方式A subagent / 方式B 内联)--> [系统初始化 agent] --生成/验证--> mcp-pack\.env
        |                                                        +--> abap\ (ZMCP_ADT FM 源码, 需部署到 SAP)
        +--委派--> [ATC 检查 agent] --调用脚本(纯 Node)--> [MCP 服务器 adt-dev] --HTTPS--> SAP (ADT/ATC/RFC)
```

**外部依赖（部署前必须就绪）**：

| 依赖 | 版本/位置 | 说明 |
|---|---|---|
| Node.js | ≥ 16（建议 LTS） | 全部脚本为纯 Node（fs/https/path/child_process），跨平台 |
| MCP 服务器 `adt-dev` | `@babamba2/abap-mcp-adt-powerup`（本部署为 v4.9.0） | 提供 ADT/ATC/文本池等工具；launcher 路径：`<根>\adt-dev\dist\server\launcher.js` |
| SAP 系统 | S/4HANA on-prem（EHP4 兼容）或 ECC | ADT 可达；`basic` 认证 |
| SAP 侧桥接 FM | `ZMCP_ADT_TEXTPOOL` / `ZMCP_ADT_DISPATCH`（函数组 `ZMCP_ADT_UTILS`） | 文本池读写必需；源码在 `agent-system_initialization\abap\` |
| OData 服务 `ZMCP_ADT_SRV` | 可选 | 仅当选择 `SAP_RFC_BACKEND=odata` 时需要；SOAP 后端不需要 |

## 3. 前置条件检查

1. **Node.js**：`node --version` 输出 ≥ 16。
2. **SAP 可达**（部署人员有账号）：
   ```bash
   curl -sk -o /dev/null -w "%{http_code}" -u "<用户>:<密码>" "<SAP_URL>/sap/bc/adt/discovery?sap-client=<Client>"
   # 期望 200
   ```
3. **MCP 服务器**：确认 `adt-dev\dist\server\launcher.js` 存在（见步骤 4.2）。
4. **网络/证书**：自签名证书场景无需额外配置（脚本已忽略 TLS 校验）。

## 4. 部署步骤

### 4.1 获取代码包
- 方式一：整体复制 `XXX升级项目` 目录到目标机。
- 方式二：解压 `XXX升级项目-初始化模板.zip` 到 `agent-system_initialization\`（旧版结构，按需合并）。
- 确认目录结构完整（见第 1 节清单）。

### 4.2 准备 MCP 服务器（adt-dev）
- 若目标机已有 `adt-dev`（如从 `your-abap-mcp\adt-dev` 复制），确保路径为：
  `<项目根>\adt-dev\dist\server\launcher.js` 或与 `.env` 同级的 `..\adt-dev\...`（脚本按 `envPath 上一级\adt-dev` 自动推断）。
- 若没有：`npm install -g @babamba2/abap-mcp-adt-powerup` 或从内部制品库获取，解压后确认 launcher.js。
- 自检：`node "<launcher>" --version`
  - ⚠ 已知问题：`adt-dev\package.json` 若带 UTF-8 BOM，`--version` 会报 JSON 解析错误（**不影响任何 MCP 调用**，可忽略；如需要可去掉 BOM）。

### 4.3 配置连接（.env）
位置：`<项目根>\mcp-pack\.env`（也可由 `agent-system_initialization` 生成，见 4.4）。

```ini
# mcp-pack/.env 模板（值按实际替换，密码勿提交 git）
SAP_URL=https://<host>:<port>
SAP_CLIENT=100
SAP_LANGUAGE=ZH
SAP_SYSTEM_TYPE=onprem
SAP_AUTH_TYPE=basic
SAP_USERNAME=<用户>
SAP_PASSWORD=<密码>
SAP_MASTER_SYSTEM=<SID，如 ZZZ>      # onprem 建对象必需
SAP_RESPONSIBLE=<用户>
```

> 关键机制（务必阅读）：
> - `.env` 只白名单加载部分键；**`SAP_PASSWORD` 建议同时写入 `.sc4sap\sap.env`**（全量加载、优先级最高），否则部分工具可能读不到密码。
> - **`SAP_RFC_BACKEND` 必须在 Node 启动前注入**（模块加载时读取，`.env`/`sap.env` 都太晚）：
>   - 本套脚本的 `mcp-invoke.js` **未显式设置时自动默认 `soap`**，一般无需手工注入；
>   - 如需覆盖（如切 odata）：Windows（PowerShell）`$env:SAP_RFC_BACKEND='soap'`，Linux/macOS `export SAP_RFC_BACKEND=soap`；
>   - 取值：`soap`（零安装，走 `/sap/bc/soap/rfc`，推荐）或 `odata`（需 `ZMCP_ADT_SRV` 已部署）。
> - 文本池/文本元素相关工具必须走 RFC 桥接，无 ADT 原生端点。

### 4.4 运行系统初始化 Agent（可选但推荐）
按 `agent-system_initialization\docs\SYSTEM_INIT_AGENT.md` 执行，它负责：系统探测 → 生成/确认 `.env` → 更新 agent-configs → 验证（启动级/只读/读写三级）。

若 SAP 侧尚无桥接 FM，需先用 `abap\` 下的源码（`zcl_zmcp_adt_dpc_ext.abap` 等）创建函数组 `ZMCP_ADT_UTILS` 与 FM（可借助 ATC 检查 Agent 的 MCP 能力 `CreateFunctionGroup`/`CreateFunctionModule` 部署到 `$TMP` 或开发包）。

### 4.5 校验调度索引与注册表
`agent-scheduler\agents-index.json` 中的 `directory` 为相对路径（`../agent-system_initialization`、`../agent-ATC_check`），从 `agent-scheduler\` 解析到同级目录即正确。校验：
```
node agent-scheduler\scripts\registry.js verify-index [agent-scheduler目录]
node agent-scheduler\scripts\scheduler-check.js [agent-scheduler目录] [--projectDir=<项目目录>]
```
- `verify-index`：逐一检查子 agent 目录与入口文档存在性；
- `scheduler-check`：前置自检（Node 版本 / registry 可运行 / 索引路径 / 注册表可写 / 项目目录可创建），全部通过 exit 0。
- 首次部署 `registry.js list` 应输出"（无已记录项目）"。

### 4.6 运行调度 Agent
按 `agent-scheduler\AGENT.md` 执行。运行时需向用户确认：

| 确认项 | 说明/默认 |
|---|---|
| 项目名称/路径（projectKey） | 每个项目唯一标识，如 `XXX-ZZZ-ZZZPROG001` |
| 连接 | `.env` 路径或连接参数 |
| ATC 变体 ID | 默认 `ZABAP_CLOUD_DEV_CHECK` |
| 创建人账号 | 拉取历史结果用（`/atc/results?createdBy=` 必填） |
| 创建日期 | 可选，用于核对结果时间 |
| 项目目录 | 本次执行产物根目录（用户指定） |
| 传输策略 | 复用可修改传输号 / 新建 / 每对象一个（执行时确认） |

流程（含状态机与断点续跑）：
1. **⓪ 前置自检**：`scheduler-check.js` 全部通过；
2. **① 收集输入**并落盘执行计划：`registry.js plan <projectKey> --name= --path= --variant= --creator= --transport= [--projectDir=]`；
3. **② 断点判断**：`registry.js status <projectKey>` 按阶段（等待初始化 / 初始化完成等待 ATC / ATC 完成等待收尾 / 全部完成）从对应步骤继续或跳过；
4. **③ 初始化**（每项目一次）：委派 `agent-system_initialization` → 成功 `registry.js init ...`（自动 step init done）/ 失败 `step init fail <原因>`；
5. **④ ATC 检查**：委派 `agent-ATC_check`（8 步）→ 完成 `registry.js add-run ...`（自动 step atc done）；
6. **⑤ 收尾**：`registry.js log` + `step complete done` + `summary <projectKey>` 生成执行总结。

## 6. 故障排查速查

| 症状 | 原因 | 处理 |
|---|---|---|
| MCP 调用 401 | `.env` 路径不对或密码未被加载 | 核对 `--env-path`；密码改走 `.sc4sap\sap.env` |
| `SAP_RFC_BACKEND must be ...` | 值非法或写在 .env（加载太晚） | 改为启动前环境变量注入，取值 soap/native/gateway/odata |
| `SAP_RFC_ODATA_SERVICE_URL is required` | 默认 odata 但没配 URL | 显式 `SAP_RFC_BACKEND=soap`，或配 URL |
| 文本池工具报 RFC 错误 | 桥接 FM 未部署 / 后端不可达 | 部署 `abap\` 源码；探测 `/sap/bc/soap/rfc` |
| ATC 结果为空/变体不对 | 拉取未指定 `checkVariant` | 走 worklist 两步流程显式传变体；列表端点必须 `createdBy` + `Accept: application/xml` |
| `corrNr could not be found` | 传输包对象未传 `transport_request` | 提供可修改传输号（`GetTransport` 确认 D 状态） |
| `Parameter createdBy could not be found` | `/atc/results` 缺创建人参数 | 步骤 1 确认创建人账号 |
| `launcher --version` JSON 报错 | package.json 带 BOM | 忽略（不影响调用）或去除 BOM |
| 传输不可用 | 请求被释放/权限不足 | `ListTransports` 找可修改请求或 `CreateTransport` |
| 调度中断 | 执行到一半停止 | `registry.js status <projectKey>` 看阶段，按 §4.6 断点从对应步骤续跑（init done→ATC；atc done→收尾） |
| `registry.js` 命令报 TypeError | 旧版注册表记录缺字段（`steps` 等） | 新版已自动迁移（normalize）；仍异常时 `clear <projectKey> --force` 重建 |
| 前置自检失败 | Node 版本/索引路径/注册表可写性问题 | 按 `scheduler-check.js` 输出逐项修复后再开始 |

## 7. 安全与维护

- **密码安全**：`.env` / `.sc4sap\sap.env` 含密码，**禁止提交 git**（项目 `.gitignore` 已排除；新环境需确认）。
- 会话中不要明文回显密码，用 `******` 代替。
- 切换 RFC 后端：改启动前 `SAP_RFC_BACKEND` 后重启客户端，无需改代码（`mcp-invoke.js` 未显式设置时自动默认 `soap`）。
- 调度注册表 `projects-registry.json` 为状态文件（执行计划 + 步骤机 + 初始化 + ATC 历史 + 日志），勿手动编辑；重置某项目用 `registry.js clear <projectKey> --force`。
- 升级 MCP 服务器：替换 `adt-dev` 后重跑初始化验证（4.4）。
